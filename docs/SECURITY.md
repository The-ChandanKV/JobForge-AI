# Security and privacy

- Keep the service bound to loopback. A single-user token enables browser login and API bearer auth. Mutating browser requests from other origins are blocked and the Host header is restricted. The Compose ports publish on loopback only.
- Originals, verified facts, generated files, and audit events live in a private database. Resume files require the same authorization as the dashboard. Export contains personal information. Deletion clears application data and pauses scheduling. Existing exports, database archives, process logs, and storage backups follow their own retention policy.
- Uploads are limited to 4 MiB. File types are PDF, TXT, and TEX. PDF import extracts text in a timed subprocess, with memory and CPU limits on supported Unix systems. The app stores originals as opaque bytes and does not serve uploaded PDFs inline. Scanned and encrypted originals require a selectable-text copy.
- The runtime compiler uses trusted Jinja2 templates, escapes profile strings, and accepts only validated geometry edits. Tectonic runs in a temporary working directory with untrusted and cached-only flags and a reduced environment. Bootstrap loads the required bundle before processing applicant data. Native process isolation is not equivalent to an OS sandbox. The Docker image runs as an unprivileged user.
- Job postings are untrusted inputs. Board slugs select from built-in HTTPS endpoints. Manual unknown URLs require pasted text. LLM completions have no tool access or credential-handling instructions and are restricted to exact verified fact IDs. Input from a JD cannot trigger a browser, shell command, or outbound submission.
- Default discovery is read-only. The browser creates a disposable isolated context for the mock host only. Real job boards use manual handoff unless the employer-authorized Greenhouse API is enabled for the exact board. Sensitive and employer-specific fields are not inferred. Optional sensitive fields are omitted. Unsupported mandatory or consent questions require manual handling.
- The live Greenhouse adapter needs employer authorization, secret credentials, explicit live settings, and existing per-application approval. Requests with uncertain status are held without automatic retry. Confirmation is recorded only with explicit evidence. The mock returns synthetic durable receipts and is safe to exercise in isolation.
- Provider transport logs hold status, timing or available usage counters, and error categories, with no credential values or captured form content. Selecting a third-party LLM exposes the relevant career facts and job text to that provider. Rules and local Ollama keep model inference on your machine.
